SSH ir raktai

  • Sukurti SSH raktų porą ir pridėti viešą raktą prie GitHub
  • Paaiškinti, kodėl privatus raktas niekada nekeliamas į Git
  • Išspręsti pirmą merge konfliktą

Pagalvokime

Prisijungiate prie serverio ir nenorite kaskart rašyti slaptažodžio.

Kaip įrodyti, kad tai jūs?

💬
Analogija

Kaip spyna ir raktas: spyną galima rodyti visiems, o raktą turi tik savininkas.

Svarbu

Raktų pora

  • Privatus raktas lieka tik jūsų kompiuteryje
  • Viešas raktas (.pub) gali būti kur nori
  • Serveris pažįsta jus pagal viešą raktą
  • Niekada nerodykite, nesiųskite ir nekelkite į Git privataus rakto

Schema

Kaip veikia prisijungimas raktu

Komandos

Raktų pora

bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_kursas -C "kursas"
ls -l ~/.ssh
bash
cut -c1-40 ~/.ssh/id_ed25519_kursas.pub
  • -f atskiras failas, kad nepersirašytų esamas raktas
  • Slaptažodinė frazė: ne tas pats kaip paskyros slaptažodis

Svarbu

Merge konfliktas

  • Dvi šakos pakeitė tą pačią eilutę skirtingai
  • Git nežino, kuri teisinga, todėl klausia jūsų
  • Ranka palikite vieną galutinį tekstą
  • Tada git add ir git commit; arba git merge --abort

Užduotis

1 užduotis: Raktų pora

Sukurti raktų porą atskirame faile ir patikrinti jos teises.

  1. Atnaujinkite main ir sukurkite šaką pamoka-06.
  2. Sukurkite ed25519 raktų porą faile ~/.ssh/id_ed25519_kursas su komentaru „kursas“ ir slaptažodine fraze.
  3. Išvardykite ~/.ssh aplanką su teisėmis ir užsirašykite, kuris failas privatus, o kuris viešas.
  4. Parodykite tik viešą raktą (pirmus kelis simbolius).
  5. Faile docs/ssh.md užrašykite, kurios dvi teisės (skaičiais) turi būti privačiam raktui ir ~/.ssh aplankui.

Užduotis

2 užduotis: Raktas GitHub'e

Pridėti viešą raktą prie GitHub ir prisijungti juo.

  1. Pagal oficialią GitHub dokumentaciją (Adding a new SSH key to your GitHub account) pridėkite id_ed25519_kursas.pub prie savo paskyros (žingsnių čia nėra, tik tikslas).
  2. Sukurkite ~/.ssh/config įrašą github.com, kuris naudoja id_ed25519_kursas.
  3. Patikrinkite prisijungimą. Pirmą kartą palyginkite serverio pirštų antspaudą su oficialiu GitHub sąraše prieš rašydami „yes“.
  4. Pakeiskite savo devops-projektas origin į SSH adresą ir patikrinkite, kad git fetch veikia.
  5. Faile docs/ssh.md užrašykite, ką darytumėte, jei privatų raktą per klaidą įkeltumėte į viešą repozitoriją.

Užduotis

3 užduotis: Sulaužyk ir pataisyk

Pamatyti, kodėl SSH atsisako per atvirų teisių, ir pataisyti.

  1. Pakeiskite privataus rakto teises taip, kad jį galėtų skaityti visi.
  2. Paleiskite prisijungimo patikrą ir užrašykite klaidos tekstą.
  3. Grąžinkite teisingas teises ir įsitikinkite, kad prisijungimas vėl veikia.
  4. Faile docs/ssh.md užrašykite klaidos tekstą ir vienu sakiniu paaiškinkite, kodėl SSH taip elgiasi.

Užduotis

4 užduotis: Merge konfliktas ir Pull Request

Sąmoningai sukelti merge konfliktą, jį išspręsti ir sulieti darbą per Pull Request.

  1. Faile docs/ssh.md skyriuje „Konfliktas“ parašykite vieną eilutę: „Raktų pora: nežinau.“ Padarykite commit šakoje pamoka-06.
  2. Sukurkite šaką pamoka-06-a, joje pakeiskite tą eilutę į „Raktų pora: du failai.“ ir padarykite commit.
  3. Grįžkite į pamoka-06 ir tą pačią eilutę pakeiskite į „Raktų pora: privatus ir viešas raktas.“ Padarykite commit.
  4. Sujunkite pamoka-06-a į pamoka-06; Git turi pranešti apie konfliktą.
  5. Išspręskite konfliktą: paliekite vieną galutinį sakinį, kuris apima abu (pvz. „Raktų pora: du failai, privatus ir viešas“), pašalinkite visus žymeklius ir užbaikite sujungimą.
  6. Nusiųskite šaką pamoka-06 į GitHub, atidarykite Pull Request į main ir sulieskite. Kompiuteryje atnaujinkite main.
  7. Patikrinkite, kad commit'e nėra privataus rakto ar jo dalies (tik žodžiai, ne turinys).
  8. ⭐ Papildomai: išsiaiškinkite pagal oficialią dokumentaciją, ką daro git merge --abort ir kada jį naudoti, ir užrašykite docs/ssh.md.
