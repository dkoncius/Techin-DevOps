Git ir GitHub nuo nulio

Įdiegsite git, prisijungsite prie GitHub, sukursite pirmą repozitoriją ir išmoksite dirbti su commit ir šakomis (branch). Visos komandos vykdomos Ubuntu terminale. Žymės išsaugomos tik šioje naršyklėje.

0 / 0

1. Paskyra ir įrankiai

  1. Užsiregistruokite github.com. Vartotojo vardą rinkitės be lietuviškų raidžių: jis bus jūsų repozitorijų adresuose, pvz., github.com/jusuvardas.

  2. sudo apt update && sudo apt install git gh -y

    git saugo projekto istoriją jūsų kompiuteryje. gh jungiasi prie GitHub svetainės.

  3. git --version
    gh --version

    Turi būti: abi komandos parodo versijos numerį, pvz., git version 2.43.0.

2. Git nustatymai

Tai atliekama vieną kartą. Vardas ir el. paštas bus matomi prie kiekvieno jūsų commit.

  1. git config --global user.name "Vardas Pavardė"
  2. git config --global user.email "jusu@pastas.lt"

    Naudokite tą patį el. paštą, kaip GitHub paskyroje, kad commit būtų susieti su jūsų profiliu.

  3. git config --global init.defaultBranch main
    git config --global core.editor nano
    git config --global core.autocrlf input
    • Pagrindinė šaka vadinsis main, kaip GitHub.
    • Kai git reikės teksto redaktoriaus, atsidarys paprastas nano.
    • Windows ir Linux eilučių pabaigos nesimaišys.
  4. git config --global --list

    Turi būti: matote user.name, user.email ir kitas ką tik nustatytas reikšmes.

3. Prisijungimas prie GitHub

  1. gh auth login

    Rodyklėmis rinkitės atsakymus ir spauskite Enter:

    • Where do you use GitHub? → GitHub.com
    • Preferred protocol? → HTTPS
    • Authenticate Git with your GitHub credentials? → Yes
    • How would you like to authenticate? → Login with a web browser

    Nusikopijuokite rodomą 8 simbolių kodą ir paspauskite Enter. Jei naršyklė neatsidaro, patys atidarykite github.com/login/device, įveskite kodą ir patvirtinkite.

  2. gh auth status

    Turi būti: Logged in to github.com account jusuvardas.

4. Pirmoji repozitorija

Projektus laikykite Linux namų aplanke (~), ne /mnt/c. Ten git veikia greičiau ir nekyla problemų su teisėmis.

  1. mkdir -p ~/projects/pirmas-projektas && cd ~/projects/pirmas-projektas
  2. git init

    Turi būti: Initialized empty Git repository in .... Git sukūrė paslėptą aplanką .git, kuriame saugo istoriją.

  3. echo "# Pirmas projektas" > README.md
  4. git status

    Turi būti: README.md raudonai, skiltyje Untracked files. Git failą mato, bet dar jo nesaugo.

  5. git add README.md

    Paleidus git status dar kartą, failas bus žalias, skiltyje Changes to be committed.

  6. git commit -m "Pridėtas README"

    Commit yra išsaugota projekto būsena su trumpu aprašymu. Aprašyme rašykite, ką pakeitėte.

  7. gh repo create pirmas-projektas --public --source=. --push

    Viena komanda sukuria repozitoriją GitHub, susieja ją su šiuo aplanku (pavadinimu origin) ir įkelia commit. Jei norite, kad repozitorija būtų matoma tik jums, vietoj --public rašykite --private.

  8. git remote -v

    Turi būti: dvi eilutės su origin https://github.com/jusuvardas/pirmas-projektas.git. Atidarę tą adresą naršyklėje, matysite savo README.md.

5. Kasdienis darbo ciklas

Taip dirbama kiekvieną kartą, kai ką nors pakeičiate projekte.

keičiate failus→git status→git add→git commit→git push
  1. echo "Mano pirmasis projektas su git." >> README.md
  2. git diff

    Turi būti: nauja eilutė pažymėta + ženklu. Iš git diff išeinama paspaudus q.

  3. git add .
    git commit -m "Papildytas README aprašymas"

    Taškas . reiškia „visi pakeisti failai šiame aplanke“.

  4. git push
  5. git log --oneline
    3f2a1c9 (HEAD -> main, origin/main) Papildytas README aprašymas a81d0e4 Pridėtas README

    Kiekvienas commit turi trumpą kodą (hash), pvz., 3f2a1c9. Juo galima nurodyti konkretų commit.

6. Šakos (branch)

Šaka yra atskira darbo linija. Naują funkciją kuriate savo šakoje, o main lieka veikianti. Kai darbas baigtas, šaką sujungiate su main.

  1. git branch

    Turi būti: * main. Žvaigždutė rodo šaką, kurioje esate.

  2. git switch -c nauja-funkcija

    -c reiškia „sukurti“. Be jo git switch tik pereina į jau esamą šaką.

  3. echo "print('Labas')" > labas.py
    git add . && git commit -m "Pridėtas labas.py"
  4. git push -u origin nauja-funkcija

    -u reikia tik pirmą kartą. Toliau šioje šakoje užteks git push.

  5. git switch main
    ls

    Turi būti: labas.py nėra, nes jis egzistuoja tik šakoje nauja-funkcija.

  6. git switch nauja-funkcija
    gh pr create --fill
    gh pr merge --merge --delete-branch

    Pull Request (PR) yra prašymas sujungti šaką su main. Komandoje jį pirma peržiūri kiti, o čia sujungiate patys. Paskutinė komanda sujungia PR, ištrina šaką ir grąžina jus į atnaujintą main.

  7. git switch main
    git merge nauja-funkcija
    git push
    git branch -d nauja-funkcija

    Šis žingsnis nereikalingas, jei jau sujungėte per PR. Tai alternatyva, kai dirbate vieni.

  8. git pull && ls

    Turi būti: labas.py dabar matosi ir main šakoje.

7. Svetimo projekto parsisiuntimas

  1. cd ~/projects && gh repo clone octocat/Hello-World

    Parsiunčia visą projektą su istorija į aplanką Hello-World. Tas pats su git: git clone https://github.com/octocat/Hello-World.git.

  2. git pull

    Įpraskite tai daryti kaskart prieš pradėdami dirbti, ypač kai prie projekto dirba keli žmonės.

Jei kas nors nepavyksta

Author identity unknown / Please tell me who you are

Git nežino jūsų vardo ir el. pašto. Atlikite 2 skyriaus žingsnius ir pakartokite git commit.

fatal: not a git repository

Esate ne projekto aplanke. Pereikite į jį, pvz.:

cd ~/projects/pirmas-projektas

Jei tai naujas projektas, paleiskite git init.

Push atmestas: rejected ... (fetch first)

GitHub yra pakeitimų, kurių jūs dar neturite. Pirma juos parsisiųskite, tada įkelkite:

git pull
git push
CONFLICT (content): Merge conflict

Ta pati failo vieta pakeista dviejose šakose. Atidarykite failą (nano failas) ir raskite žymes:

<<<<<<< HEAD jūsų versija ======= kita versija >>>>>>> nauja-funkcija

Palikite tai, kas teisinga, ištrinkite žymių eilutes ir išsaugokite. Tada:

git add . && git commit -m "Išspręstas konfliktas"
Authentication failed / Permission denied

Prisijunkite iš naujo ir leiskite git naudoti gh prisijungimą:

gh auth login
gh auth setup-git
gh auth login neatidaro naršyklės

Tai įprasta WSL. Paspauskite Enter, Windows naršyklėje patys atidarykite github.com/login/device ir įveskite terminale parodytą kodą.

error: src refspec main does not match any

Bandote daryti push, kai dar nėra nė vieno commit. Pirma padarykite git add . ir git commit -m "...".

Atsidarė keistas redaktorius ir nežinau, kaip išeiti

Jei tai vim (apačioje ~ ženklai): paspauskite Esc, įveskite :wq ir Enter. Jei tai nano: Ctrl+O, Enter, Ctrl+X. Kad visada atsidarytų nano:

git config --global core.editor nano
Git rodo, kad pakeisti visi failai, nors nieko nekeičiau

Dažniausiai kalti Windows eilučių pabaigos (projektas po /mnt/c). Nustatykite ir projektą laikykite ~ aplanke:

git config --global core.autocrlf input
Netyčia įtraukiau slaptažodį ar .env failą

Jei dar nepadarėte push: git restore --staged .env, tada įrašykite .env į .gitignore. Jei jau įkėlėte į GitHub, slaptažodį ar raktą būtinai pakeiskite, nes istorijoje jis lieka matomas.
