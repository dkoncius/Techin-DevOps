# 3 užduotis: Nusiklonuokite savo repozitoriją

Jei kas neveikia: perskaitykite klaidą, ieškokite dokumentacijoje ir užsirašykite, kas padėjo. Dirbtinio intelekto šiose užduotyse nenaudojame. Galite remtis ankstesnio dėstytojo pateikta Git komandų santrauka (`git komandos.pdf`, pridėta Teams'e). Taip pat [Git ir GitHub sąrašas](https://raw.githack.com/dkoncius/Techin-DevOps/main/kursas/checklists/Git%20ir%20GitHub%20s%C4%85ra%C5%A1as.html) (nustatymai, prisijungimas, šakos, klaidų sprendimai).

1. **Tikslas:** Nusiklonuoti savo repozitoriją iš GitHub į kompiuterį ir joje pakartoti darbą su šaka: pakeitimas, commit, sujungimas, šakos trynimas.
2. Terminale aplanke `devops` nusiklonuokite repozitoriją `git-svetaine` ir pereikite į jos aplanką.
3. Patikrinkite: aplanke yra `devops-dokumentas.md`, nuotolinė nuoroda rodo jūsų repozitoriją, o commit istorijoje yra commit'as iš GitHub svetainės.
4. Kompiuteryje papildykite dokumentą skyriumi „Kur gali lūžti“: 2 vietos, kur grandinė gali lūžti, kiekviena su vienu sakiniu kodėl. Padarykite commit su žinute „Pridėta, kur gali lūžti“.
5. Nusiųskite commit'ą į GitHub ir naršyklėje patikrinkite, kad pakeitimas atsirado.
6. Sukurkite šaką `skyriai` ir persijunkite į ją.
7. Šakoje `skyriai` papildykite dokumentą skyriumi „Kodėl DevOps“: 2 sakiniai, kuo DevOps naudingas komandai. Padarykite commit su žinute „Pridėta, kodėl DevOps“.
8. Nusiųskite šaką `skyriai` į GitHub (naršyklėje turi atsirasti šaka `skyriai`).
9. Grįžkite į `main` ir įsitikinkite, kad skyriaus „Kodėl DevOps“ dokumente dar nėra.
10. Sujunkite `skyriai` į `main` ir nusiųskite `main` į GitHub.
11. Ištrinkite šaką `skyriai` kompiuteryje ir GitHub'e.
12. Išsiaiškinkite pagal oficialią dokumentaciją, kuo skiriasi šakos trynimas mažąja ir didžiąja raide. Atsakymą užrašykite dokumento skyriuje „Git“, padarykite commit su žinute „Pridėta apie šakų trynimą“ ir nusiųskite.
13. Patikrinkite, kad dokumente ir repozitorijoje nėra slaptažodžių ar realių IP.
14. **Kodėl:** vienu sakiniu užrašykite, kuo `clone` skiriasi nuo `git init` su `git remote add` ir kodėl po `clone` nieko papildomai susieti nereikia.
15. **Papildomai:** pažaiskite [Learn Git Branching](https://learngitbranching.js.org/) pirmą lygių grupę arba parašykite dokumente, kas yra merge commit.
